# OpsFlow前端产品与视觉设计计划

日期：2026-09-10。当前为设计计划，尚未实现前端。基于已交付Java后端，采用Vue3 + TypeScript，先做桌面工作台，同时保证手机端提交、查看和回复可用。

## 1. 从用户任务推导界面

用户进入系统需要立即回答三个问题：哪些事情需要我处理？事情进行到哪里？下一步可以做什么？页面层级围绕这三个问题建立。

| 用户 | 主要任务 | 默认落点 | 首屏重点 |
|---|---|---|---|
| 普通用户 | 描述问题、补充信息、了解进度 | 我的工单 | 待我补充的事项、近期工单、新建入口 |
| 客服 | 接单、理解上下文、回应并解决 | 我的工作台 | 待接单、处理中、等待用户；每条工单的下一步 |
| 组长 | 消除升级问题、调配人力 | 团队待办 | 已升级工单、待分配事项、当前负载 |
| 管理员 | 维持组织与规则运转 | 管理概览 | 配置是否齐备、异常处理入口、业务概览 |

每个角色只出现有权限的导航；兼任角色可切换“我的工单”和“服务工作台”，切换只改变视图，不改变实际权限。保留最近一次工作视图，首次登录使用角色默认值。

设计取舍：不采用登录后先看四张巨大数字卡片的常见后台首页；把有限的首屏空间交给可执行任务。统计保留独立入口。只在有真实可执行事项时展示提示，不做虚构的健康评分。

## 2. 导航与页面结构

```text
登录 / 注册
我的工单          所有登录用户，可与客服工作视图并存
服务工作台        客服、组长、管理员，内容按权限收敛
团队待办          组长、管理员
统计              组长、管理员
管理              管理员
  用户与角色 / 客服组 / 分类 / SLA规则 / 消费异常
通知              顶部入口，点击定位到具体工单
个人菜单          当前账号、退出；客服显示在线状态
```

桌面左侧导航约208px，顶部栏56px；主内容随窗口伸缩。页面标题、筛选、列表沿同一左边线排列。工单详情使用独立路由，支持复制链接和浏览器返回；返回列表保留筛选和滚动位置。第一版以整页详情为主，不叠加抽屉、弹窗和多层详情。

管理中的消费异常不是日常工单导航；权限、分配规则和SLA编辑集中放在管理页，避免操作人员在处理过程中进入配置流程。

## 3. 工单列表：先识别，再决定

```text
┌────────────┬───────────────────────────────────────────────┐
│ OpsFlow    │ 我的工作台                          通知  账号 │
│            ├───────────────────────────────────────────────┤
│ 我的工单   │ 我的工作台                         在线 ●     │
│ 服务工作台 │ 待接单   处理中   等待用户   已解决             │
│ 团队待办   │ 查找工单…    分类 ▾   优先级 ▾   更多筛选       │
│ 统计       ├───────────────────────────────────────────────┤
│            │ 工单与问题           状态      责任人  时限    │
│            │ #1042 VPN连接失败    待接单    陈敏   响应剩18分│
│            │ #1038 邮箱无法收信   处理中    陈敏   解决已超时│
│            │ #1025 软件安装失败   等待用户  陈敏   明日到期  │
│            ├───────────────────────────────────────────────┤
│ 管理       │                              上一页   下一页  │
└────────────┴───────────────────────────────────────────────┘
```

示例姓名、编号、时间仅表达排版，不是当前系统数据。

- 标题是主信息，编号和分类为辅助；状态、优先级、SLA是三个不同维度，不用一种红色混为一谈。
- 默认列控制在6列左右；标题允许两行，描述不整段铺开。点击行进入详情，键盘可聚焦标题链接。
- 待办队列优先显示即将违约的事项；已解决列表按最近更新时间排序。该排序必须由后端执行。
- 首次响应未完成时突出响应时限；完成后突出解决时限。悬停或详情查看两个确切截止时间；倒计时不闪烁，不显示秒级跳动。
- 分页优先采用真实的上一页/下一页和hasMore，不为漂亮分页编造总条数。标签上的数量只有服务端提供同口径聚合后才显示。
- 搜索只在全量权限范围内查询；后端尚无关键词检索时，不用筛选当前页冒充全局搜索。
- 第一版不做拖拽看板：业务状态转换有明确前置条件和说明要求，采用有名称的动作更可靠。

## 4. 工单详情：问题、交流、行动

宽屏采用主内容与约300px侧栏；主区显示问题原文、公开交流和回复编辑器，侧栏显示状态、责任人、时限、分类及附件。阅读区域控制在约65–80个字符宽度，不让一行描述铺满整个屏幕。

```text
返回列表   #1042 VPN连接失败                待接单    [开始处理]
─────────────────────────────────────────────────────────────
问题描述和原始附件                     │ 负责客服 / 客服组
                                      │ 优先级 / 分类 / 标签
交流记录   操作记录                    │ 首次响应截止时间
用户：连接公司网络时出现错误提示……     │ 解决截止时间
客服：请补充错误截图……                 │ SLA升级记录
                                      │
回复用户 / 内部备注                    │ AI辅助（展开）
输入回复内容……                        │ 摘要 / 回复建议
                              [发送回复]│
```

主操作随当前状态和实际身份变化，不同时堆满七个状态按钮。

| 当前状态 | 普通用户可做 | 工作人员可做，仍需资源授权 |
|---|---|---|
| CREATED | 回复、修改、取消 | 管理者分配；无候选人时说明原因 |
| ASSIGNED | 回复、查看进度 | 仅被分配的客服开始处理；适格人员转派 |
| PROCESSING | 补充信息 | 回复、等待用户、标记已解决、转派 |
| PENDING | 补充信息 | 恢复处理、回复、转派 |
| RESOLVED | 查看、补充回复 | 关闭；组长/管理员受限重开 |
| CLOSED / CANCELLED | 查看归档内容 | CLOSED可由组长/管理员受限重开；CANCELLED无重开入口 |

权限不是仅按表中角色决定：还需校验是否为本人、负责人或本组管理者；服务端仍为最终判定。用户回复PENDING工单不会自动恢复状态；界面明确提示“已补充，等待客服继续处理”。普通用户不出现“确认关闭”，当前后端关闭动作属于工作人员。

等待用户与标记已解决会把说明写入公开交流，弹窗必须标明“此说明将发送给用户”。取消、关闭、重开和跨组转派用一次包含结果说明的确认；普通回复不反复确认。内部备注使用明确的独立标签和“仅内部可见”提示，切换到公开回复时不自动带出内部内容。

## 5. 创建工单：一次把问题说清楚

独立页面、单列表单，不用步骤条拆成多页。必填标题、问题描述、分类、优先级；有有效SLA时优先默认NORMAL，否则让用户从服务端返回的可用优先级中选择，不提交没有规则的组合。标签和附件为可选。分类帮助文案给出问题示例，不要求用户知道客服组名称。

附件在创建前本地暂存，创建成功后按顺序上传，每次使用最新version；上传失败保留“工单已创建”事实，提供单个附件重试，不能让用户重复创建工单。提交成功跳到详情，显示下一步和真实时限，不弹出多余的成功页面。

一次提交绑定不可变请求快照和幂等键。超时重试使用同一快照/键；用户修改内容后属于新尝试，先避免原请求结果未知导致重复工单。提交中禁止重复操作，离开有未保存内容时提示。

AI在工单创建后异步提供分类建议，不作为表单必经步骤；若用户确实不知道分类，可由管理员配置具有有效SLA的“待分类”分类。不能仅在前端写死一个并不存在的默认分类ID。

## 6. AI辅助的交互边界

- 展开后再按需加载；默认不占据大块屏幕，不提供独立聊天入口。
- 分类显示“建议分类、建议优先级、理由、置信度”，注明是模型自评，非经验证准确率。仅CREATED且版本一致时提供采纳。
- 已分配或版本变化时，建议保留供参考，显示不可直接采纳的原因；不绕过后端约束。
- 回复建议先进入可编辑草稿框。“使用草稿”不会发送；客服按“发送回复”才写公开评论。
- 当前AI采纳接口只接受version，不能提交修改后的草稿。编辑后的建议通过普通评论接口发送；不把它伪记为原建议已采纳。需要追踪编辑后采纳时另补明确的服务端协议。
- 摘要只读，可重新生成。PENDING、PROCESSING、FAILED、DISABLED分别显示排队、生成中、可重试、未启用；主工单操作始终可用。
- 模型、Token和调用耗时放到“调用记录”中，按已有权限开放，不占据客服主要操作区。

## 7. 组长与管理员

团队页分为升级事项、待人工分配、成员负载。用紧凑表格展示成员在线状态、处理中数量、活动量，避免用饼图迫使用户估算谁有空。跨组转派只能选择实际授权且可分配的客服，不把所有用户暴露给普通客服。

统计页先解释时间范围与分母，再展示每日趋势、分类数量和响应/解决时长。无样本用“暂无数据”，不填0%；日报标记最后刷新时间与“待刷新”。当前工作量单列说明不受创建日期范围限制。颜色不能让用户误以为AI采纳率等于准确率。

管理配置使用标准列表加编辑表单；不做万能表单引擎。SLA字段使用“首次响应须在…分钟内”“解决须在…分钟内”，同时解释自然时间和PENDING不暂停。启停、角色调整及重放提供明确影响范围与必填原因。

## 8. 视觉语言：清爽、有秩序的服务工作台

品牌记忆点放在工单行与详情侧栏的细窄SLA标识上；其余空间保持安静。以留白、文字对齐、细分隔线建立层级，减少卡片套卡片、大阴影和渐变背景。

| 设计令牌 | 选择 |
|---|---|
| 画布 | 雾灰 #F4F7F8 |
| 内容表面 | 白色 #FFFFFF |
| 主文字 | 深蓝灰 #172B32 |
| 次要文字 | 灰蓝 #607078 |
| 主操作/选中 | 青蓝 #087E8B |
| 分隔线 | 浅灰 #E2E8EC |

语义色另设：危险#B42318、预警#946200、完成#24734D；仅用于真实状态并配文字/图标。开发时验证实际前景/背景组合对比度，不能只凭色值宣称通过可访问性测试。

- 字体：中文采用本机苹方/微软雅黑UI，西文Segoe UI Variable或系统sans-serif；不依赖外网字体。表格数字启用等宽数字特性，但不把全部元信息换成程序员等宽字体。
- 字号：页标题24px、区块标题18px、正文14–16px、辅助文字12–13px；中文正文行高约1.6。重要内容不用过细字重。
- 间距采用4/8/12/16/24/32px；列表行约60px。输入框与按钮约40px高，触屏交互目标至少44px。
- 控件圆角6px、弹层10–12px；阴影只用于浮层。图标采用同一线性风格，常用按钮保留文字。
- 动效仅用于开合、悬停和反馈，约120–180ms；遵守减少动态效果设置。第一版只精做好浅色主题。

## 9. 响应式、错误与可访问性

≥1200px显示详情双栏；768–1199px收窄导航、侧栏折叠；<768px导航收起、列表变成保留标题/状态/时限的紧凑条目，详情信息改为可展开区域，回复按钮在不遮挡内容的位置可达。复杂规则编辑优先桌面，不让普通用户的手机建单流程受影响。

| 情况 | 界面行为 |
|---|---|
| 首次无工单 | 提供“创建工单”和简短说明 |
| 筛选无结果 | 展示当前筛选，可一键清除 |
| 401 | 保留当前页意图，重新登录；账号切换时清除旧账号草稿和缓存 |
| 403 | 明确无权限，不把它显示为网络故障 |
| 409 | 保留输入，提示工单已变更；取得真实新版本后由用户重新确认，不自动重发写操作 |
| 429 | 按Retry-After展示等待时间，停止重复请求 |
| 断网/5xx | 保留编辑内容，提供有边界的手动重试；不凭空更新业务状态 |
| 附件/AI局部失败 | 局部提示，不覆盖已创建工单或已发送回复 |

表单有可见标签、字段级错误及汇总定位；弹窗管理焦点、Esc关闭及返回原触发点。完整键盘路径、焦点样式、文字对比度和读屏状态反馈作为验收项。文本默认按纯文本渲染，禁止将评论或AI输出未经处理当HTML显示。

## 10. 与现有接口的接缝

已核对TicketController、WorkflowService、SupportController、UserMapper及README。以下是计划中的补充，不表示当前后端已经支持。

| 缺口 | 用户影响与最小补充 |
|---|---|
| 工单列表只有status/categoryId/offset/limit，且返回数组 | 补充本人创建/本人负责/本组视图、优先级、关键词、SLA截止排序等服务端筛选；权限取交集，绝不靠当前页过滤伪造队列 |
| 工单/评论主要返回用户及分类ID | 在授权DTO中补充所需显示名称，避免表格全是ID或前端N+1查询；不返回密码等账号内部字段 |
| 管理员可修改用户，但没有用户列表/选择器API | 增加管理员分页用户查询及角色筛选，为组长、客服配置提供姓名选择器 |
| 普通用户无法查询分类对应的有效优先级 | 可用分类DTO补充可提交的优先级选项；没有有效规则时明确显示不可创建，服务端创建时仍重新校验 |
| 普通客服无权调用组成员列表 | 增加按具体工单授权的可转派候选接口，返回有效目标及必要显示信息 |
| 列表没有全量计数或hasMore | 可用limit+1生成hasMore；阶段一不要求昂贵总数。队列徽标需独立一致口径计数才上线 |
| 409之后详情可能仍命中30秒服务端缓存 | 补充受同样权限约束的强制新鲜详情读取机制；浏览器no-cache不能绕过当前Redis缓存 |
| 通知只有分页及已读操作 | 第一版入口不显示虚构未读数；需要徽标时补未读计数接口 |

前后端本地开发优先Vite代理/api，生产同源反向代理；不通过允许任意来源来解决跨域。沿用Bearer鉴权，第一版令牌保存在内存，刷新页面需要重新登录并保留返回地址；不把JWT长期放localStorage。若以后需要无感续期，单独设计HttpOnly会话/刷新令牌及CSRF边界。

## 11. 前端实现边界

Vue3、TypeScript、Composition API、`<script setup>`；Vue Router负责路由，原生fetch封装统一响应、鉴权和AbortSignal。Pinia仅在确实需要跨页面共享会话/偏好时引入，不把所有表单状态全局化。样式使用CSS变量和组件样式；组件库在高保真稿确定后按可访问性及表格/表单能力选择，不先堆依赖或后台模板。

```text
frontend/src/
  app/                 应用壳、路由与会话
  api/                 按业务组织的类型及请求函数
  features/tickets/    列表、详情、创建及工作流
  features/team/       团队待办
  features/statistics/ 指标与趋势
  features/admin/      配置管理
  components/          实际被复用的状态、时限、弹窗等控件
  styles/              设计令牌与基础样式
```

| 组件 | 单一职责与数据流 |
|---|---|
| TicketFilters | 接收筛选值，通过update:modelValue发出变更 |
| TicketList | 接收items/loading/hasMore，发出open/page请求 |
| SlaIndicator | 接收deadline/completedAt/now及累计违约标记，区分当前周期与历史违约，不发起请求 |
| TicketConversation | 接收已授权交流记录，显示公开/内部边界 |
| ReplyComposer | 接收发送状态，发出submit(content,internal)；拥有本地草稿 |
| TicketActions | 接收工单与实际能力，发出具体动作；不自行覆盖工单状态 |
| AiSuggestionPanel | 显示分析状态与草稿，发出request/useDraft/accept请求 |

请求随路由和筛选变化取消，只有最新响应可以更新页面；状态变化成功后替换服务端返回值。前端允许动作的计算集中维护并测试，服务端权限校验不能省略。通知和任务轮询仅在页面可见且确有需求时进行，失败退避，避免撞到120次/分钟限流。

## 12. 分阶段实施与验收

| 阶段 | 交付 | 必须验证 |
|---|---|---|
| F0 产品契约 | 角色任务、页面线框、设计令牌、必要API接缝与DTO | 已完成原型和工作台接口契约；浏览器原型检查通过 |
| F1 用户闭环 | 登录、我的工单、创建、详情、公开回复、附件 | 真实浏览器已验证注册/登录、建单/编辑、附件上传删除、回复与手机取消；组件测试与构建通过 |
